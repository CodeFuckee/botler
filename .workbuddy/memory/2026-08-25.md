# 2026-08-25 工作日志

## 诊断 10.0.0.122 部署登录卡死问题

用户反馈 10.0.0.122:8080 登录后卡死。经 curl 探测发现：

- **端口 8080**：运行的是 nginx 静态托管的 "Docker Monitor" Flutter Web 应用，与 Botler 无关。所有 /api/* 路径被 SPA fallback 拦截返回 index.html，导致前端 JS 无法获取真实 API 数据 → 卡死。
- **端口 8000**：才是 Botler 的实际部署（uvicorn + FastAPI），`/api/health` 返回 ok:true，版本 v1.6.86，MinIO 和磁盘均正常，调度器有 1 running / 4 queued 任务。

结论：用户访问了错误的端口。Botler 实际跑在 8000 上且健康。若需 8080 入口，需修复 nginx 配置将其 proxy_pass 到 127.0.0.1:8000（参考 deploy/nginx-terminal.conf）。

## 诊断 10.0.0.122:8000 登录后卡死问题（根因已定位）

- **根因链**：CI 部署（v1.6.86，14:01）按 issue #467 创建 `backend/data → data/backend/data` 软链保 secret → 14:25 任务 #710（botler 仓库，`local_path` 就是生产目录）执行 `prepare_workspace` 时 `git clean -fd` 删除了该软链 → `get_session_secret()` 发现文件丢失，重新生成新 secret → 所有已登录会话全部失效 → 401 风暴，前端跳 `/login?error=session_expired`。
- **关键坑**：`.gitignore` 中 `backend/data/`（带尾斜杠）只匹配目录不匹配符号链接，所以 `git clean -fd` 会删掉未被忽略的软链（已本地 git 实验验证）。
- **次要疑点**：SSO 配置 `redirect_uri: https://home.chenkaidi.top:448/api/auth/callback`，与用户实际访问的 `http://10.0.0.122:8000` 不同源；14:26-14:36 的重登尝试在日志中无 callback 记录，待用户确认 Synology SSO 页面表现。
- **已做止血**：把当前生效的 secret（backend/data/session_secret.key，14:25 生成）同步覆盖到持久化目录 data/backend/data/session_secret.key，两份 md5 一致，无需重启服务。
- **建议修复**：① `.gitignore` 增加 `backend/data`（无尾斜杠）以保护软链；② pm2 环境变量固定 `BOTLER_SESSION_SECRET=/home/ckd/codes/botler/data/backend/data/session_secret.key`，彻底摆脱对 backend/data 形态的依赖；③ 服务器 swap 8G/8G 满载，可关注。
