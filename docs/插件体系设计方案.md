# Botler 插件体系设计方案（issue #140）

> 版本: v1.0 | 日期: 2026-08-17 | 状态: 已实现
> 需求: 「平台想要实现一个插件体系，把执行引擎、大模型 api 供应商、webhook 发送任务消息
> 都做成插件的形式，设计一个实现方案」

## 1. 需求背景与目标

Botler 平台目前有三类「能力」以硬编码方式内聚在核心模块中，扩展新能力需要修改核心代码：

| 能力 | 现状 | 位置 |
|---|---|---|
| 任务执行引擎 | `worker.engine` 三选一（claude / hermes / dsh），`_run_once` 内 if/else 分发 | `executor.py` |
| 大模型 API 供应商 | 生图模型 provider 二选一（gemini_nano_banana / openai_gpt_image），`generate()` 内 if/else 分发 | `image_models.py` |
| 任务消息发送通道 | 网页通知（`Notifier`）与 webhook 推送（`WebhookPusher`）分别硬编码调用 | `notifier.py` / `webhook_push.py` |

本方案引入一个轻量**插件体系**，把以上三类能力统一为「插件」：

1. **统一抽象**：插件分类、插件接口、插件注册表、配置驱动；
2. **内置迁移**：现有实现封装为内置插件，行为完全向后兼容（配置字段不变、默认行为不变）；
3. **开放扩展**：新增引擎 / 供应商 / 发送通道只需实现插件接口并注册，零改动核心模块。

## 2. 设计原则

- **向后兼容**：现有 `config.yaml` 全部字段与默认行为不变，存量部署零迁移成本；
- **最小侵入**：插件采用「适配器委托」模式，复用现有实现内部逻辑，不重写引擎/客户端；
- **单一注册表**：所有插件在全局注册表中登记，调用方只面向注册表编程；
- **先测试后实现**：插件框架配套单元测试先行，全量回归保证行为一致。

## 3. 插件模型

### 3.1 插件分类（PluginKind）

| 分类 | 含义 | 内置插件 |
|---|---|---|
| `executor` | 任务执行引擎 | claude / hermes / dsh |
| `model_provider` | 大模型 API 供应商 | gemini_nano_banana / openai_gpt_image |
| `notifier` | 任务消息发送通道 | webhook / in_app |

### 3.2 插件对象（Plugin）

```python
@dataclass(frozen=True)
class Plugin:
    kind: PluginKind      # 插件分类
    name: str             # 插件标识（注册表键，配置项引用）
    description: str      # 插件说明（设置页/文档展示）
    version: str          # 插件版本（内置插件 "1.0"）
```

插件是**纯数据描述 + 实现委托**：内置插件把「分类 + 标识 + 实现」登记进注册表，
调用方（executor / ImageModelClient / 收尾流程）按 `kind + name` 取出插件并调用其能力。

### 3.3 插件注册表（PluginRegistry）

```python
class PluginRegistry:
    def register(self, plugin: Plugin) -> None: ...   # 重复注册抛 PluginConflictError
    def get(self, kind: PluginKind, name: str) -> Plugin: ...      # 未注册抛 PluginNotFoundError
    def names(self, kind: PluginKind) -> list[str]: ...            # 列出某分类全部插件名（有序）
    def list(self, kind: PluginKind) -> list[Plugin]: ...          # 列出某分类全部插件
    def has(self, kind: PluginKind, name: str) -> bool: ...
    def load_external(self, module_paths: list[str]) -> list[str]: ...  # 加载外部插件模块
```

- 全局单例：`get_registry()`，进程内共享；
- **内置插件自动注册**：`botler/plugins/` 包导入时注册；
- **外部插件加载**：`worker.plugin_paths` 配置的 Python 模块路径列表，应用启动时
  `importlib` 逐个加载（模块内调用注册函数完成登记），实现零改动扩展。

## 4. 三类插件接口设计

### 4.1 执行引擎插件（ExecutorPlugin）

```python
class ExecutorPlugin(Plugin):
    kind = PluginKind.EXECUTOR

    def run(self, executor, task_id, repo, issue,
            resume_session=None, resume_history=None) -> tuple[int, str]:
        """执行一次任务引擎，返回 (exit_code, output)。

        executor 为运行时的 ClaudeExecutor 实例（提供工作区/日志/事件
        总线等基础设施）；内置插件委托 executor 的既有引擎实现，
        自定义插件可实现完全独立的引擎逻辑。
        """
```

- `executor._run_once` 改为：`plugin = registry.get(EXECUTOR, engine); return plugin.run(...)`；
- 未知引擎名回退 claude（与现状一致）。

### 4.2 大模型供应商插件（ImageProviderPlugin）

```python
class ImageProviderPlugin(Plugin):
    kind = PluginKind.MODEL_PROVIDER
    default_base_url: str = ""   # 内置预设默认地址
    default_model: str = ""      # 内置预设默认模型

    def generate(self, client, prompt, image=None, *,
                 mime_type="image/png", size=DEFAULT_SIZE, n=1) -> list[ImageResult]:
        """按配置调用供应商接口生成图片。client 为 ImageModelClient 实例。"""
```

- `ImageModelClient` 构造时按 provider 查注册表（未知 provider 报错，与现状一致）；
- `generate()` 委托插件：`plugin.generate(self, prompt, image, mime_type=..., size=..., n=...)`；
- 内置预设信息（默认 base_url / model）收敛到插件对象，`IMAGE_MODEL_PRESETS` 由注册表派生。

### 4.3 任务消息发送插件（NotifierPlugin）

```python
class NotifierPlugin(Plugin):
    kind = PluginKind.NOTIFIER

    def send_task_succeeded(self, context, task, repo_name="",
                            repo_url="", issue=None) -> dict | None: ...
    def send_task_failed(self, context, task, reason, repo_name="") -> dict | None: ...
    def send_test(self, context, repo_name="测试仓库") -> dict: ...
```

- 收尾时**遍历全部 notifier 插件**分发：webhook 插件自检 `webhook.enabled` 与地址
  未配置则跳过（返回 None）；in_app 插件按数据库唯一索引幂等；
- 容错策略不变：任一通道失败仅记日志，绝不阻塞任务收尾。

## 5. 内置插件清单与迁移

| 分类 | 插件名 | 实现 | 迁移说明 |
|---|---|---|---|
| executor | `claude` | Claude Code CLI 无头模式 | `_run_once` 的 claude 分支抽出为 `_run_claude_once`，插件委托 |
| executor | `hermes` | hermes runner 脚本 | 委托 `_run_hermes_once`（逻辑不动） |
| executor | `dsh` | deepseek-harness SDK | 委托 `_run_dsh_once`（逻辑不动） |
| model_provider | `gemini_nano_banana` | Gemini generateContent | `_generate_gemini` 迁入插件类 |
| model_provider | `openai_gpt_image` | OpenAI images API | `_generate_openai` 迁入插件类 |
| notifier | `webhook` | 外部 Webhook HTTP 推送 | 包装 `WebhookPusher`（issue #136） |
| notifier | `in_app` | 网页通知事件 | 包装 `Notifier`（issue #21） |

## 6. 调用方改造点

```text
backend/botler/
  plugins/            # 新增：插件体系核心
    __init__.py       #   包入口：导入内置插件并导出 get_registry
    base.py           #   PluginKind / Plugin / PluginRegistry / register_plugin
    executors.py      #   执行引擎插件（claude/hermes/dsh）
    models.py         #   大模型供应商插件（gemini/openai）+ ImageResult 等类型
    notifiers.py      #   任务消息发送插件（webhook/in_app）
  executor.py         # _run_once 改注册表委托；收尾遍历 notifier 插件
  image_models.py     # generate() 改注册表委托；类型从 plugins.models 再导出
```

- `config.example.yaml`：新增可选 `worker.plugin_paths` 示例（外部插件扩展点）；
- `README.md`：新增「插件体系」章节；
- `docs/插件体系设计方案.md`：本文档。

## 7. 配置设计

现有配置字段**全部保留不变**（`worker.engine` / `claude` / `hermes` / `dsh` /
`image_models` / `webhook` / `notifications`），仅新增可选扩展点：

```yaml
worker:
  engine: claude          # 不变：引用 executor 插件名
  plugin_paths: []        # 新增（可选）：外部插件 Python 模块路径列表，
                          #   启动时加载并注册（如 ["/opt/botler-plugins/my_engine.py"]）
```

> 外部插件模块约定：模块内调用 `botler.plugins.base.register_plugin(...)` 完成注册；
> 加载失败仅记日志告警，不阻塞应用启动（与 webhook 推送同容错策略）。
