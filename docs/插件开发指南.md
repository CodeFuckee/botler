# Botler 插件开发指南

> 版本: v1.0 | 日期: 2026-08-19 | 面向对象: 插件开发者
> 插件体系的整体设计与迁移背景见 [`docs/插件体系设计方案.md`](插件体系设计方案.md)
> （接口定义 / 迁移清单 / 测试计划 / 演进方向），本文档聚焦**如何开发一个新插件**：
> 从零编写 → 注册 → 配置启用 → 测试 → 上线。

## 1. 插件体系概览

Botler 把三类「能力」统一为**插件**：任务执行引擎、大模型 API 供应商、
任务消息发送通道（另有识图供应商一类，issue #152 扩充）。所有插件登记在
全局插件注册表（`botler.plugins.PluginRegistry`）中，调用方只面向注册表
编程——新增能力只需实现插件接口并注册，**核心模块零改动**。

| 插件分类（PluginKind） | 能力 | 内置插件 | 配置入口 |
|---|---|---|---|
| `executor` | 任务执行引擎（`worker.engine` 选择） | `claude` / `hermes` / `dsh` | `worker.engine` |
| `model_provider` | 生图大模型 API 供应商 | `gemini_nano_banana` / `openai_gpt_image` | `image_models[].provider` |
| `vision_model_provider` | 识图（视觉理解）API 供应商 | `gemini_vision` / `openai_vision` / `custom` | `vision_models[].provider` |
| `notifier` | 任务消息发送通道（任务收尾自动分发） | `webhook` / `in_app` | 插件自检启用条件 |

**插件 = 分类（`kind`）+ 标识（`name`）+ 描述（`description`）+ 版本（`version`）+ 能力方法**。
`name` 是注册表键，也是配置项引用的名字，同分类内必须唯一。

## 2. 快速开始：第一个外部插件

外部插件是一个**独立的 Python 模块文件**，模块内调用 `register_plugin()` 完成登记，
通过 `worker.plugin_paths` 配置在应用启动时加载。三步即可接入：

**Step 1：编写插件模块**（示例：一个最简单的外部插件 `/opt/botler-plugins/echo_engine.py`）：

```python
"""自定义执行引擎插件示例（外部插件模块）。"""
from botler.plugins import ExecutorPlugin, register_plugin


class EchoEnginePlugin(ExecutorPlugin):
    name = "echo"                       # 插件标识（worker.engine 引用它）
    description = "回声引擎：原样返回任务标题（示例插件）"
    version = "1.0"

    def run(self, executor, task_id, repo, issue,
            resume_session=None, resume_history=None):
        """执行一次任务引擎，返回 (exit_code, output)。"""
        return 0, f"echo: {issue.get('title', '')}"


# 模块导入即注册（外部插件加载时执行到这一行完成登记）
register_plugin(EchoEnginePlugin())
```

**Step 2：配置 `worker.plugin_paths`**（`config.yaml`，参考
`backend/config.example.yaml` 中该段的注释）：

```yaml
worker:
  engine: claude        # 默认执行引擎（可改为 echo 启用上面的示例插件）
  plugin_paths:         # 外部插件 Python 模块路径列表
    - /opt/botler-plugins/echo_engine.py
```

**Step 3：启动并验证**：

```bash
# 启动日志会出现：
# INFO 外部插件加载成功: /opt/botler-plugins/echo_engine.py
# 或在插件管理页（/plugins）看到 echo 出现在「执行引擎」分组
cd backend && .venv/bin/python -m pytest tests/test_plugins.py -q   # 插件体系测试
```

> 加载失败只记日志告警、**不会阻塞应用启动**（与 webhook 推送同容错策略）。

## 3. 插件模型与注册表 API

### 3.1 插件基类 `Plugin`

```python
from botler.plugins import Plugin, PluginKind

# 声明式风格：子类用类属性声明 kind / name / description / version
# 也可用构造参数覆盖（kind/name/description/version 均可传）
plugin = Plugin(kind=PluginKind.EXECUTOR, name="demo", description="演示")
```

| 字段 | 说明 |
|---|---|
| `kind` | 插件分类（`PluginKind` 枚举），见 §1 表格 |
| `name` | 插件标识，注册表键 + 配置引用名，同分类唯一 |
| `description` | 插件说明（设置页 / 插件管理页展示），建议中文 |
| `version` | 插件版本，内置插件为 `"1.0"` |

### 3.2 注册表便捷函数（全局注册表单例）

```python
from botler.plugins import (
    PluginKind, register_plugin, get_plugin,
    has_plugin, list_plugins, plugin_names,
)

register_plugin(MyPlugin())              # 注册到当前注册表（返回插件本身）
get_plugin(PluginKind.EXECUTOR, "echo")  # 按 kind + name 取插件，未注册抛 PluginNotFoundError
has_plugin(PluginKind.NOTIFIER, "webhook")   # 是否存在
list_plugins(PluginKind.NOTIFIER)        # 某分类全部插件（注册顺序）
plugin_names(PluginKind.EXECUTOR)        # 某分类全部插件名
```

### 3.3 `PluginRegistry` 完整方法（注册表实例）

| 方法 | 说明 |
|---|---|
| `register(plugin)` | 登记插件；同名同分类重复注册抛 `PluginConflictError` |
| `get(kind, name)` | 取插件；未注册抛 `PluginNotFoundError`（错误信息附带当前可选名） |
| `has(kind, name)` | 是否存在 |
| `names(kind)` / `list(kind)` | 某分类插件名 / 插件列表（注册顺序） |
| `load_external(paths, errors=None)` | 加载外部插件模块，返回成功加载的路径列表；失败仅记日志 |
| `registered_external(path)` | 某路径模块注册的全部 `(kind, name)` |
| `path_of(kind, name)` | 外部插件来源路径（内置插件返回 `None`） |
| `remove_external(path)` | 按来源路径移除该模块注册的全部插件（幂等） |
| `clear_external()` | 清空全部外部插件（重载前调用） |

> 全局单例 `get_registry()` 进程内共享；内置插件在 `botler.plugins` 包导入时
> 自动注册（`backend/botler/plugins/__init__.py`，导入顺序即展示顺序）。

## 4. 四类插件接口详解

### 4.1 执行引擎插件 `ExecutorPlugin`（kind = `executor`）

```python
from botler.plugins import ExecutorPlugin, PluginKind, register_plugin

class MyEnginePlugin(ExecutorPlugin):
    kind = PluginKind.EXECUTOR   # 基类已声明，可省略
    name = "my_engine"
    description = "我的自定义执行引擎"
    version = "1.0"

    def run(self, executor, task_id, repo, issue,
            resume_session=None, resume_history=None) -> tuple[int, str]:
        """执行一次任务引擎，返回 (exit_code, output)。

        - executor：运行时的 ClaudeExecutor 实例（提供工作区 / 日志 /
          事件总线 / 停止请求等基础设施）；
        - resume_session / resume_history：断点续跑上下文（issue #8）——
          resume_session 为上次会话 id（claude / dsh 引擎语义），
          resume_history 为上次会话历史（hermes 引擎语义）；
        - 返回非 0 exit_code 视为任务失败（失败收尾流程接管）。
        """
        return 0, "任务执行输出"
```

**启用方式**：`config.yaml` 的 `worker.engine` 填插件 `name`：

```yaml
worker:
  engine: my_engine
```

> `ClaudeExecutor._run_once` 按 `worker.engine` 查插件并委托执行；**未注册的
> 引擎名回退 `claude`**（与现状一致），配置拼写错误不会直接报错。

**内置参考实现**：`backend/botler/plugins/executors.py`（`claude` / `hermes` / `dsh`
均为适配器委托既有引擎实现，内部逻辑不动）。

### 4.2 生图供应商插件 `ImageProviderPlugin`（kind = `model_provider`）

```python
import base64

from botler.plugins import (ImageModelError, ImageProviderPlugin,
                              ImageResult, PluginKind, register_plugin)

class MyImageProvider(ImageProviderPlugin):
    kind = PluginKind.MODEL_PROVIDER
    name = "my_image"
    display_name = "我的生图供应商"        # 设置页预设展示名
    description = "示例生图供应商插件"
    default_base_url = "https://api.example.com/v1"   # 内置预设默认地址
    default_model = "my-image-1"                       # 内置预设默认模型
    version = "1.0"

    def generate(self, client, prompt, image=None, *,
                 mime_type="image/png", size="1024x1024", n=1) -> list[ImageResult]:
        """按 prompt（+ 可选参考图片）生成图片，返回 ImageResult 列表。

        - client：ImageModelClient 实例（提供 base_url / api_key / model /
          _http 客户端）；
        - 失败抛 ImageModelError（带请求地址与响应摘要，便于诊断）。
        """
        resp = client._http.post(
            self.resolve_request_url(client.base_url, "/images/generations"),
            headers={"Authorization": f"Bearer {client.api_key}"},
            json={"model": client.model, "prompt": prompt, "n": n, "size": size,
                  "response_format": "b64_json"},
        )
        if resp.status_code >= 400:
            raise ImageModelError(
                f"请求失败: HTTP {resp.status_code} {resp.text[:200]}")
        # 解析响应中的图片数据，包装为 ImageResult(mime_type, data) 列表
        results = []
        for item in resp.json().get("data") or []:
            results.append(ImageResult(
                mime_type="image/png",
                data=base64.b64decode(item["b64_json"])))
        return results


register_plugin(MyImageProvider())
```

**`resolve_request_url(base_url, api_path)` 语义（issue #150，生图 / 识图一致）**：

- 自定义完整端点（`base_url` 非空且**不等于** `default_base_url`，如代理网关
  `https://grsai.dakka.com.cn/v1/draw/completions`）→ **原样直接使用**，不再拼接操作路径；
- 未配置 / 等于预设默认（尾斜杠归一比较）→ 按官方接口拼接操作路径
  （如 `/images/generations`、`/models/{model}:generateContent`）。

**启用方式**：`config.yaml` 的 `image_models` 列表（`provider` 填插件 `name`，
选择预设时自动填充 `default_base_url` / `default_model`，均可修改）：

```yaml
image_models:
  - name: 我的生图
    provider: my_image
    base_url: https://api.example.com/v1
    api_key: ${MY_IMAGE_API_KEY}
    model: my-image-1
    enabled: true
```

**内置参考实现**：`backend/botler/plugins/models.py`
（`gemini_nano_banana` / `openai_gpt_image`）。

### 4.3 识图供应商插件 `VisionProviderPlugin`（kind = `vision_model_provider`）

```python
from botler.plugins import VisionProviderPlugin, PluginKind, register_plugin

class MyVisionProvider(VisionProviderPlugin):
    kind = PluginKind.VISION_MODEL_PROVIDER
    name = "my_vision"
    display_name = "我的识图供应商"
    description = "示例识图（视觉理解）供应商插件"
    default_base_url = "https://api.example.com/v1"
    default_model = "my-vision-1"
    # 是否支持以 http(s) URL 传图（issue #163/#164）：
    #   OpenAI 兼容接口 → True（强制走 MinIO http URL，禁止 base64 内联）；
    #   Gemini generateContent → False（仅支持 base64 inline_data）
    supports_image_url = True
    version = "1.0"

    def describe(self, client, image, *,
                 mime_type="image/png", prompt="") -> str:
        """描述图片内容，返回文本描述。

        - client：VisionModelClient 实例（提供 base_url / api_key / model）；
        - 失败抛 VisionModelError（带请求地址与响应摘要）。
        """
        return "图片描述（示例）"


register_plugin(MyVisionProvider())
```

**启用方式**：`config.yaml` 的 `vision_models` 列表（结构与 `image_models` 相同，
`provider` 填插件 `name`）。内置预设：`gemini_vision` / `openai_vision` /
`custom`（自定义 OpenAI 兼容视觉模型）。

> ⚠️ 自 issue #164 起：`supports_image_url = True` 的识图插件**禁止 base64 内联**
> ——图片先 SHA-256 哈希上传 MinIO，识图请求传 http(s) URL；未启用 / 配置
> 不完整时识图测试明确报错引导，不静默回退。

**内置参考实现**：`backend/botler/plugins/vision_models.py`。

### 4.4 消息发送通道插件 `NotifierPlugin`（kind = `notifier`）

```python
from botler.plugins import NotifierPlugin, PluginKind, register_plugin

class MyNotifier(NotifierPlugin):
    kind = PluginKind.NOTIFIER
    name = "my_channel"
    description = "示例任务消息发送通道"
    version = "1.0"

    def send_task_succeeded(self, context, task, repo_name="", repo_url="",
                            issue=None) -> dict | None:
        """任务成功消息。未启用返回 None（调用方跳过）；失败抛异常。"""
        settings = context.config.get()    # Settings 视图（dataclass，属性访问）
        if not (settings.webhook_url or "").strip():
            return None                    # 示例：未配置地址 = 未启用
                                           # （与内置 webhook 插件同模式）
        # ... 调用外部通道 API ...
        return {"ok": True}

    def send_task_failed(self, context, task, reason, repo_name="") -> dict | None:
        """任务失败（需人工介入）消息。未启用返回 None。"""
        return None

    def send_test(self, context, repo_name="测试仓库") -> dict:
        """设置页「测试发送」：验证通道配置可用性。"""
        return {"ok": True}


register_plugin(MyNotifier())
```

**分发语义（重要）**：

- 任务收尾时**遍历全部已注册 notifier 插件**分发，各通道自检启用条件
  （如 webhook 检查 `webhook.enabled` 与地址，未配置返回 `None` 跳过）；
- **任一通道失败仅记日志，绝不阻塞任务收尾**（调用方统一容错）；
- `context` 为运行时的 ClaudeExecutor 实例（提供 `config` / `db` / `notifier` 等）。
- **幂等建议**：内置 `in_app` 靠数据库唯一索引幂等（同一任务收尾只记一次）；
  自定义通道应自行保证重复分发不产生重复消息。

**内置参考实现**：`backend/botler/plugins/notifiers.py`（`webhook` / `in_app`）。

## 5. 外部插件加载机制

### 5.1 `worker.plugin_paths`（启动加载）

```yaml
worker:
  plugin_paths:
    - /opt/botler-plugins/my_engine.py
    - /opt/botler-plugins/feishu_channel.py
```

应用启动（`backend/botler/main.py` 的 `build_context`）时逐个
`importlib` 加载并注册：

- 模块内调用 `register_plugin()` 完成登记（加载进哪个注册表就注册进哪个）；
- 模块名按路径哈希唯一化（`_botler_plugin_<hash>`），同一路径重复加载幂等
  由注册表冲突检测兜底；
- 加载 / 注册失败**仅记日志告警，不阻塞应用启动**。

### 5.2 插件管理页（issue #145，Web UI `/plugins`）

| 操作 | 后端接口 | 说明 |
|---|---|---|
| 列表 | `GET /api/plugins` | 按分类分组展示全部插件（内置 / 外部来源、供应商预设、`worker.engine` / `plugin_paths` 上下文） |
| 安装 | `POST /api/plugins/install` | 输入外部插件模块路径：校验文件存在 / 模块可加载且至少注册一个插件 / 与已装插件无同名同分类冲突 → 通过后写入 `worker.plugin_paths` 并**热加载**（无需重启） |
| 卸载 | `POST /api/plugins/uninstall` | 仅外部插件可卸载（配置与注册表同时移除；内置插件带「内置」徽章不可卸载） |
| 重载 | `POST /api/plugins/reload` | 按当前 `plugin_paths` 清空并重载全部外部插件 |
| 设置 | `PUT /api/plugins/settings` | 默认执行引擎（executor 插件，复用 `worker.engine`）+ 外部插件重新加载 |

> 安装安全策略：路径只接受部署机本地 Python 模块文件；任何校验失败 400 拒绝
> **且不落盘**（热加载失败防御性回滚配置）。

## 6. 配置与启用速查

| 插件分类 | 配置段 | 字段 |
|---|---|---|
| executor | `worker.engine` | 引擎插件 `name`（未注册回退 `claude`） |
| model_provider | `image_models[]` | `provider`（插件 `name`）/ `base_url` / `api_key` / `model` / `enabled` |
| vision_model_provider | `vision_models[]` | 同上（`provider` 为识图插件 `name`） |
| notifier | 无需配置段 | 各通道自检启用条件（如 `webhook.enabled`、`notifications` 等）；webhook 插件复用设置页 webhook 段配置 |

- `api_key` 等敏感字段支持 `${ENV}` 环境变量引用（与 `image_models` 同模式）；
- 插件自带预设（`default_base_url` / `default_model`）在设置页选择时自动填充，
  用户可修改覆盖。

def test_echo_engine_run_returns_tuple():

## 8. 最佳实践与约定

1. **向后兼容**：不修改现有配置字段与默认行为；新能力 = 新插件 + 可选配置段；
2. **最小侵入**：优先「适配器委托」模式——复用现有实现内部逻辑，不重写核心；
3. **容错第一**：通道 / 供应商失败抛具体异常（`ImageModelError` /
   `VisionModelError` 等，附请求地址与响应摘要），由调用方统一记日志；
   外部插件加载失败绝不阻塞应用启动；
4. **幂等**：消息发送等有副作用的能力自行保证重复调用安全；
5. **命名**：`name` 建议小写下划线；同分类内全局唯一；
6. **注释与描述用中文**（与仓库一致）；`description` 面向设置页 / 插件页用户；
7. **`base_url` 语义**：自定义完整端点直接使用；用户填 404 时在错误信息中
   引导补全完整路径（不能只填域名）；
8. **先测试后实现**：插件框架配套单元测试先行，全量回归保证行为一致；
9. **提交规范**：新插件作为代码变更提交时前缀 `feat:`；纯文档 `docs:`；
   issue 引用使用全角括号（issue #NN）。

## 9. 常见问题（FAQ）

**Q1：注册时报 `PluginConflictError: 插件重复注册`**
同分类下 `name` 已被占用（内置或其他外部插件）。换一个 `name`，或先卸载
冲突的外部插件。

**Q2：`get_plugin` 报 `PluginNotFoundError: 插件未注册`**
`kind` / `name` 拼写有误，或外部插件未加载成功（检查启动日志
「外部插件加载失败」、`plugin_paths` 路径、模块内是否真的调用了
`register_plugin`）。错误信息会附带当前该分类可选插件名。

**Q3：`worker.engine` 配了不存在的引擎名**
不会报错——回退 `claude`（与现状一致）。确认 `plugin_paths` 已配置且启动
日志显示加载成功。

**Q4：自定义 `base_url` 请求返回 404 page not found**
自定义 `base_url`（不等于预设默认）会被**原样作为完整请求地址**直接使用，
不再拼接接口操作路径——请填写含完整路径的地址（如
`https://api.example.com/v1/draw/completions`），不能只填域名。

**Q5：如何让新插件不重启就生效？**
插件管理页「安装」写入配置并热加载；修改插件代码后点「重新加载」（或
`POST /api/plugins/reload`）。

**Q6：外部插件加载失败会怎样？**
仅记日志告警，应用正常启动（与 webhook 推送同容错策略）；请查看日志中的
异常堆栈修复模块后重载。
